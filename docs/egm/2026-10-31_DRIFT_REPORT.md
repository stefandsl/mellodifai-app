# mellodifai drift report (31/10/2026)

Read-only audit: every place where the code diverges from its design documents. Matching behavior is not listed.
Line references are `file:line` relative to `C:\Users\Asus\Documents\mellodifai` unless an absolute engine path is given.

## 2026-10-31-mellodifai-design.md

- Known/deferred: the any-topic "general" lyric-video theme (spec 9.1, lines 148-152) does not exist. Every project is forced to the VBP theme: `supabase/migrations/20261031000006_web_flow.sql:33` inserts `'vbp'`, the drafting prompt is VBP-only (`apps/worker/src/stages/draft-lyrics.ts:47`, validation `"vbp"` at `:184`), and the web hardcodes `theme="vbp"` (`apps/web/components/project-workspace.tsx:101`, `apps/web/app/actions/checkpoints.ts:18`).
- Known/deferred: the worker does not start at logon through Windows Task Scheduler and nothing restarts it on crash (spec line 85-86). It is started by hand (`README.md:13-17`); `apps/worker/scripts/` contains only `backup.ps1` and `import-legacy.ts`.
- The UI never shows the "busy" worker state (spec line 58). The badge only renders online/offline (`apps/web/components/worker-badge.tsx:66-71`); the `worker.busy` dictionary key (`packages/shared/src/i18n.ts:68`) is unused, and `busy_job_id` is not readable by the browser (`supabase/migrations/20261031000012_worker_busy_job_fk.sql:7-8`).
- `workers.engine_version` (spec line 103) is never populated: `main.ts` builds `WorkerLoop` without `engineVersion` (`apps/worker/src/main.ts:106-115`), so the upsert always writes `null` (`apps/worker/src/loop.ts:155`).
- Take scores (spec lines 24, 99, 110) are never computed. `createTake` is called without `scores` (`apps/worker/src/stages/generate-song.ts:238-247`) and the engine's `tools/score_takes.py` is never invoked; the take picker prints the raw empty JSON object (`apps/web/components/take-picker.tsx:38-40`).
- The LLM does not write the display map (spec line 107). `draft_lyrics` asks only for title, lyrics, style, exclude and l10n (`apps/worker/src/stages/draft-lyrics.ts:47-55`) and copies the display map from the reference language's shipped file (`apps/worker/src/stages/draft-lyrics.ts:90`, `:134`).
- Danger-spot checks after `timing` (spec lines 112-113, 139-140) are not implemented: no chant count before the Final Chorus and no outro-greeting detection, `tools/clip_whisper.py` is never called. `timing` only cuts two listening clips (`apps/worker/src/stages/timing.ts:73-95`) and goes straight to `storyboard` (`apps/worker/src/stages/timing.ts:117-119`), so no flag becomes a checkpoint; the web never reads `qa_flags` at all (no reference anywhere in `apps/web`).
- QA blocking gates are incomplete (spec lines 116, 138-139): only integrated loudness, true peak, crushed words and a duration check exist (`apps/worker/src/stages/qa.ts:87-107`). Pace vs target (`tools/pace_meter.py`), stamp overshoot and the lyric gate (`tools/lyric_gate.py`) are missing.
- The optional Gemini jury button (spec lines 116, 140) does not exist in the web app or the worker.
- Browser previews are 480p capped at 15 MB, not 720p (spec lines 89, 26): `scale=-2:480` and the 15 MB limit in `apps/worker/src/stages/render.ts:22`, `:64-65` and `apps/worker/src/preview.ts:19`, `:39`.
- The `art` stage produces no cover (spec lines 89, 118) and makes the thumbnail with the Pillow script `tools/make_thumb.py` (`apps/worker/src/stages/art.ts:5-22`) instead of GPT Image via `codex exec` with kie fallback (spec line 61). The uploaded thumbnail path is also not stored on any row (`apps/worker/src/stages/art.ts:22`).
- The publish metadata form is not fully prefilled (spec lines 27-28): it has only title, description, tags and chapters (`apps/web/components/project-workspace.tsx:485`), with no thumbnail or captions fields, and chapters are derived from `versions.storyboard_sections` (`apps/web/lib/publication-defaults.ts:247-268`), a column that no stage ever writes (`apps/worker/src/stages/storyboard.ts:13` sets only `storyboard_path`), so chapters are always empty.
- The project library is thinner than described (spec lines 29-30): the grid shows only topic, per-language status chips and update date (`apps/web/app/(app)/library/page.tsx:22-25`, `:57-90`), is server-rendered with no Realtime (not a live status), and no page offers downloads.
- CI does not run on every push (spec line 35): push builds are limited to `main` (`.github/workflows/ci.yml:4-5`).
- The weekly `pg_dump` is not run by the worker (spec line 159): it is a standalone script (`apps/worker/scripts/backup.ps1`) that the README leaves to optional manual scheduling (`README.md:38`).
- The VBP back-fill (spec lines 143-144) imports no YouTube ids (no publication rows are created in `apps/worker/src/legacy-import.ts:96-142`), creates one placeholder take per language without kie task id or audio preview and marks it chosen (`apps/worker/src/legacy-import.ts:113-119`), and uploads 480p previews under the `video-720p.mp4` key (`apps/worker/src/legacy-import.ts:206`, `:216`).

## 2026-10-31-mellodifai-platform.md

- Tech stack says Next.js 15 (plan line 9); the web app uses Next.js 16 (`apps/web/package.json:21`, `"next": "16.4.3"`).
- Tech stack says Postgres 15 (plan line 9); local Supabase runs Postgres 17 (`supabase/config.toml:41`).
- The web app holds a third env var, `NEXT_PUBLIC_SITE_URL` (`apps/web/lib/redirect-url.ts:13`, `apps/web/playwright.config.ts:28`), against "only `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`" (plan line 17).
- Worker secrets are not loaded from the three fixed files (plan line 18): `loadSecrets` reads only the `;`-separated list in `WORKER_ENV_FILES` (`apps/worker/src/secrets.ts:45`) and loads nothing when it is unset.
- CI runs on push only for `main` (`.github/workflows/ci.yml:4-5`), not on every push (plan line 75).
- RLS does not give the admin role cross-owner access (plan line 107: "role = 'admin' or owner_id = auth.uid() for customers"): every table policy requires `owner_id = auth.uid()` for admins too (`supabase/migrations/20261031000001_core.sql:170-234`, `supabase/migrations/20261031000002_queue.sql:47-67`); only the storage policy has the admin branch (`supabase/migrations/20261031000001_core.sql:246-259`).
- `claim_job` returns `setof public.jobs` (empty set when idle) instead of `returns jobs` / null (plan line 102): `supabase/migrations/20261031000002_queue.sql:74`, `supabase/migrations/20261031000005_pipeline_hardening.sql:35`.
- Engine `display.ts` still has the 11 static `display-map.json` imports (`C:\Users\Asus\Documents\suno-remake\motion\src\components\a\display.ts:8-18`); the `fetchJson` path is used only in workspace mode (`C:\Users\Asus\Documents\suno-remake\motion\src\lib\data.ts:39`), not as a replacement (plan line 121).
- Engine staging files are named `<name>.part<ext>` (for example `video.part.mp4`), not `<file>.part` (plan line 138): `apps/worker/src/engine.ts:112-117`.
- File structure: the library is `apps/web/app/(app)/library/page.tsx` with a redirect in `apps/web/app/page.tsx`, not `app/(app)/page.tsx` (plan line 55).
- There is no `import_legacy` stage (plan lines 52, 187): no `stages/import-legacy.ts`, the registry has no `import_legacy` handler (`apps/worker/src/stages/index.ts:11-22`); the import exists only as `apps/worker/src/legacy-import.ts` driven by `apps/worker/scripts/import-legacy.ts`.
- `draft_lyrics` does not ask the LLM for the full VBP pack JSON (plan line 151): the model writes only title, lyrics, style, exclude and l10n (`apps/worker/src/stages/draft-lyrics.ts:47-55`); the display map is copied from the reference language (`:134`) and settings are fixed by the worker (`:72-92`).
- The `generate_song` idempotency key is `generate_song:<versionId>:<generation>` (`supabase/migrations/20261031000006_web_flow.sql:50`, later `generate_again` variants), not `generate:<versionId>:<attempt>` (plan line 152).
- `timing` danger-spot flags (plan line 153) omit the chant count via `tools/clip_whisper.py` and the outro-greeting presence check; only crushed words are counted and two clips are cut (`apps/worker/src/stages/timing.ts:62-115`).
- Render previews (plan line 155: 720p, crf 30, max 40 MB) are 480p, crf stepped from 30 up to 42, max 15 MB (`apps/worker/src/stages/render.ts:12-65`); the video-review player therefore shows 480p, not 720p (plan line 169).
- `qa` (plan line 156) has no pace check with `tools/pace_meter.py` and no stamp-overshoot check (`apps/worker/src/stages/qa.ts:87-107`).
- Fake doubles (plan line 160) do not copy fixtures: they synthesize audio, video and a thumbnail with ffmpeg at runtime (`apps/worker/src/fake/index.ts:33-97`).
- The take picker "scores" (plan line 169) are always empty because the worker never writes `takes.scores` (`apps/worker/src/stages/generate-song.ts:238-247`).
- Publish form chapters are never actually prefilled (plan line 169): `publicationDefaults` reads `versions.storyboard_sections` (`apps/web/lib/publication-defaults.ts:247`), which no worker stage writes (`apps/worker/src/stages/storyboard.ts:13`).
- Not every enqueue uses a deterministic idempotency key (plan line 171): `confirm_publication` appends `gen_random_uuid()` to the `set_privacy` key (`supabase/migrations/20261031000005_pipeline_hardening.sql:98`) and `resolve_kie_submission` does the same for `generate_song` (`supabase/migrations/20261031000009_final_fixes.sql:45`).
- Login shows no allowlist refusal (plan lines 169, 182): refused addresses get the same "link sent" notice as accepted ones (`apps/web/components/login-form.tsx:15-18`), and the auth E2E asserts that neutral response (`apps/web/e2e/auth.spec.ts:5`).
- Legacy import (plan line 187) uploads 480p previews of at most 15 MB under the historic `video-720p.mp4` key instead of ~28 MB 720p previews (`apps/worker/src/legacy-import.ts:206`, `:216`; `apps/worker/src/preview.ts:19`, `:39`), and back-fills one placeholder take (take 1, no kie id, no audio) as the chosen take instead of the real takes (`apps/worker/src/legacy-import.ts:113-119`).
- Known/deferred: no `apps/worker/scripts/install-task.ps1` and no scheduled task at logon with restart on failure (plan line 190); the worker is started by hand (`README.md:13-17`).
- The weekly `pg_dump` (plan line 190) exists as `apps/worker/scripts/backup.ps1` but nothing schedules it (`README.md:38` leaves it optional).

## README.md

- Deploy step 2 (`README.md:26`) implies that allowlisting the email is enough before the admin's first sign-in, but the code never creates the auth user on a magic-link request: signups are disabled (`supabase/config.toml:177`) and the login form sends `shouldCreateUser: false` (`apps/web/components/login-form.tsx:40`). The admin user must first be created through the Supabase admin API or dashboard (as the E2E setup does in `apps/web/e2e/global-setup.ts:18-22`); the README does not say so.
- `README.md:32` says both production domains are trusted redirect targets, but `redirectUrl` trusts only the single host in `NEXT_PUBLIC_SITE_URL` (`apps/web/lib/redirect-url.ts:13`, `:34`), so an auth callback on `www.mellodifai.com` is redirected to the `NEXT_PUBLIC_SITE_URL` origin instead of staying on `www`.
