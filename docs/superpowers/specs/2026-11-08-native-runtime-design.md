# Native runtime for MellodifAI

**Status:** design for M8, 2026-11-08. Implementation is gated by the Windows spike gaps below. Docker remains a supported runtime. This document does not authorize a production cutover.

## Goal and boundary

Run the existing Supabase API contract and MellodifAI services without Docker on Windows x64, macOS and Linux. Preserve the same Postgres 17 data, JWT and RLS behavior, storage URLs, Realtime events, backup and restore guarantees, and M1 production hardening. Do not replace Supabase Auth or PostgREST with an incompatible API. Keep `MELLODIFAI_ROOT` as the runtime root and TypeScript in `ops/` as the control plane, per section 25 of the master design.

This branch is based on `build/studio-ui`, which has no `ops/` package. The implementation must start after M1's `ops/stack.ts`, `ops/services.ts`, and migrations have landed on the integration branch. The M1 plan defines the existing `stack.ts <render|start|stop|migrate|reset|env-file> --env <env>` interface. Native mode extends that interface; it does not create a second stack manager.

## Evidence and decision

The 2026-11-08 spike report at `E:/mellodifai/codex-streams/no-docker/spike-report.md` is outside this repository. On Windows, native PostgreSQL 17.11 and PostgREST 16.5 ran on private ports. A tiny gateway returned 401 for a missing `apikey` and proxied REST and Auth health successfully. Supabase Auth v2.197.0 built only after a spike-local removal of its Unix `SO_REUSEPORT` call, then served `/health`. The unmodified Storage v1.84.19 dependency install failed because `fs-xattr` declares `os: !win32`; its file backend imports that package directly. The first app migration failed at `storage.buckets` after the Supabase Postgres init scripts, since Storage service migrations had not run. Realtime is required by `use-live-refresh.ts`, `use-job-progress.ts`, and `live-timeline.tsx`; it was not yet run natively on Windows. Thus a complete native stack is **not proven**. `pnpm test:db` and Playwright against it cannot be reported green.

Use upstream service implementations with version and build provenance pinned in a native manifest. Prefer [Supabase Slim Services native archives](https://github.com/supabase/slim-services/blob/main/HOST_NATIVE_ARTIFACTS.md) for Linux amd64/arm64 and macOS arm64 when their exact versions and full stack behavior are validated. They are experimental, service-level artifacts, not a proven complete stack, and publish no Windows or macOS x64 target. For Windows x64, use [EDB's portable PostgreSQL 17 zip](https://www.postgresql.org/download/windows/), the [PostgREST Windows release](https://postgrest.org/en/stable/explanations/install.html), and reproducible native builds of Auth, Storage, and Realtime with the Windows fixes established in the plan. macOS x64 needs the same source-build fallback or a tested upstream binary. Do not silently substitute service versions across platforms.

| Required part | Version baseline | Native role and gap |
| --- | --- | --- |
| PostgreSQL | 17.11 | Data and Supabase roles, schema, extensions. Windows EDB archive starts; Supabase bootstrap plus service migrations are still required. |
| Auth | v2.197.0 | Email sign-in, admin API, JWTs. Windows build requires a portable listener path. |
| PostgREST | v16.5 | REST and RPC over RLS. Windows binary starts with PostgreSQL's `libpq` on `PATH`. |
| Storage | v1.84.19 | File objects and signed URLs. Windows file backend needs a durable metadata implementation replacing POSIX `fs-xattr`, upstreamed if possible. |
| Realtime | v2.151.3 | Postgres change subscriptions. BEAM release and full subscription test required on Windows. |
| Gateway | small Node service in `ops/` | Loopback `/auth/v1`, `/rest/v1`, `/storage/v1`, `/realtime/v1` proxy, WebSocket upgrade, `apikey` enforcement, request limits. Spike gateway covered only HTTP routes. |
| Studio, edge runtime, analytics | none | The app does not call them. They stay absent from native dev and production; Mailpit or the configured SMTP sender is still needed for email tests and sign-in. |

The API gateway must match the M1 edge-proxy boundary: bind loopback, forward only declared routes, remove client supplied identity headers, validate `apikey` against current anon/service keys without logging them, and preserve Authorization, Range, signed URL query strings, streaming uploads, and WebSocket upgrade. Auth public endpoints still require the project's `apikey` as the current gateway does. A service-key request does not bypass the M1 ops layer or its spending limits. TLS remains at the existing edge proxy and tunnel. Keep Postgres, service ports, and admin ports unreachable from the LAN.

## Data and startup contract

`ops/stack.ts ... --runtime docker|native --env dev|e2e|ci|prod` defaults to `docker` for existing installations. `MELLODIFAI_RUNTIME=native` may set the default for service supervision; an explicit CLI flag wins. The environment table from M1 remains the source of project IDs, URLs and ports. Native uses the same external API URL and environment file names, but puts service listeners on private loopback ports. A separate native dev or e2e stack has its own data directory, object directory, config, secrets, and port range. The shared e2e API on 45621 and the live API on 54321 are never reused by a spike or an implementation test.

The native startup sequence is: verify artifacts and disk, lock the stack, start Postgres, apply versioned Supabase database init scripts and service migrations, apply MellodifAI migrations in filename order, start Auth, PostgREST and Storage, start Realtime and its migrations, then start the gateway. Each step checks readiness before the next. Partial database initialization writes a pending witness and fails closed on restart. Native `reset` is allowed only for isolated dev/e2e/ci roots, never production. Every app migration is transactionally recorded by filename and checksum; a changed applied migration is an error. `test:db` and Playwright run only after the gateway, Auth, Storage, REST, and Realtime probes pass.

The source of Supabase roles, `auth` and `storage` schemas is the pinned [Supabase Postgres migration set](https://github.com/supabase/postgres/tree/develop/migrations/db), followed by the pinned Auth and Storage service migrations. The first app migration references `auth.users`, `auth.uid()`, `storage.buckets`, and `storage.objects`; the native installer must supply all four before applying it. Keep the Supabase Postgres extension and preload matrix matched to the selected release. The branch's 35 app migrations do not create extensions, but future M1 migrations and service code may require `pg_net`, `pgsodium`, `vault`, `pg_cron`, `supautils` or other extensions. Build or package each required extension for the exact PostgreSQL major and OS; do not stub database functions or omit an extension merely to make startup pass.

Store mutable database, objects, logs and temporary files under `<MELLODIFAI_ROOT>/stacks/<env>/native`; immutable artifacts under `<MELLODIFAI_ROOT>/cache/native/<service>/<version>/<platform>-<arch>`. On a machine with a different root, require the owner to set `MELLODIFAI_ROOT` to a non-system data volume. Refuse initialization when C: has less than 20 GB free on Windows. Secrets stay in the existing M1 secret files and process environment with owner-only permissions; no values in arguments, URLs printed to logs, manifest files, or repository files. Native role passwords must be distinct and survive restart, unlike CLI-managed container defaults. Preserve M1's default-password probe and port-owner checks with a host-native equivalent.

## Artifact supply and upgrades

Commit a manifest of exact service version, supported OS/architecture, source URL, SHA-256, licence and notice file, and required runtime libraries. Installer downloads to a temporary path on the runtime root, verifies SHA-256 before extraction, checks path traversal, extracts atomically into the cache, and never executes an unchecked download. For build-from-source targets, CI produces signed or checksum-pinned archives and an SBOM; the development PC does not compile them during routine startup. Include notices for [PostgreSQL](https://www.postgresql.org/about/licence/) (PostgreSQL License), [Auth](https://github.com/supabase/auth/blob/master/LICENSE) and [PostgREST](https://github.com/PostgREST/postgrest/blob/main/LICENSE) (MIT), and [Storage](https://github.com/supabase/storage/blob/master/LICENSE) and [Realtime](https://github.com/supabase/realtime/blob/main/LICENSE) (Apache 2.0), plus transitive runtime licences. Validate redistribution terms of the particular EDB archive before shipping it inside an installer.

Upgrade is backup-first and one stack at a time. Stop writers, take a verified `pg_dump` plus object snapshot, stage the new artifact set, run service and app migrations, run health and RLS probes, then switch service launchers. Database migrations may be irreversible; if a post-migration probe fails, restore the verified backup and the previous artifact set, rather than starting old binaries on a newer schema. Keep the Docker runtime runnable for existing installations. A Docker-to-native move is an explicit maintenance operation: stop all writers, export roles/schema/data and objects, import into a fresh native data directory, compare counts and object hashes, run all probes, and switch only the gateway URL after success. No production switch is automatic.

## Supervision on each OS

One TypeScript process supervisor owns dependency order, readiness, shutdown, restart policy and status. Thin wrappers install operating system startup hooks and pass only the runtime root and stack name. On Windows, M1's `ops/services.ts` installs separate owner and restricted service accounts or Scheduled Tasks with `AtStartup` triggers; production installation still needs the owner's elevated action for ACLs, accounts and firewall. On macOS, install per-user `launchd` agents in `~/Library/LaunchAgents` and use an owner-run launch daemon only if pre-login startup is required. On Linux, use `systemd --user` units with lingering when unattended startup is needed. The wrappers invoke the same Node `ops/stack.ts` command and never duplicate rendering or upgrade logic. Stop dependents before Postgres and wait for a clean checkpoint. A process exit leaves a bounded restart trail under the runtime root and cannot start the public tunnel until all required probes and the M1 hardening checks pass.

## Environment behavior and exit gate

- **Dev:** choose Docker or native with one flag, same app config and fake providers. No paid credits.
- **E2e and CI:** isolated native root and ports, `WORKER_FAKE=1`, local mail catcher or deterministic fake SMTP, full database and Playwright suites. Test both runtime modes in CI.
- **Production:** preserve M1 role isolation, tunnel route policy, backup, restore, owner sign-in, paid-call ledger and service role restriction. Native mode remains unavailable until the Windows, macOS and Linux matrices pass.

Exit requires native cold start, restart after power loss, migration from an empty database, Docker-to-native restore rehearsal, `pnpm test:db`, `pnpm e2e`, a real browser at 1440x900 and 1360x600, Realtime delivery and polling recovery, upload/download/signed URL/Range behavior, SMTP sign-in, and M1 security probes on every supported OS. A Windows Storage metadata or Realtime gap blocks the release. Linux/macOS artifact smoke alone is insufficient.
